1 · Parse — parseQuery()

Tokenize like the index, so query and document never

disagree on what a word is: lowercase · don't → dont ·

coca-cola → coca cola · café → cafe [fold_diacritics]

a corpus can swap in its own [term_normalizer]

"quoted words" → phrase: all words required, adjacency

checked in stage 6 on a positional index [phrase_mode]

+word / -word → required / excluded (also -"phrase")

word* → prefix; object-orient* = object + orient*

word^2 → boost, on any of the above

Numbers digits joined by . : / - are one unit, searched as

an adjacent phrase of the parts [compound_numbers]

3.14 · 10:30 · 2024-05-01 · 192.168.0.1 · 1/2 (−3.14 excludes)

v2.0, f-16 and roman numerals stay ordinary words

Digits are exact a token with a digit is never fuzzed (co2, 1998)

Query shape noted for the auto algo (routing table below):

has a wildcard · has a question word (who, what, when…) ·

is a single word (excluded words don't count)

2 · Expand — variants remember origin, class, boost

Stopwords removed from optional words if a list is passed

(demo default: on — questions 0.60 → 0.93 MRR)

Stems rule-based, both directions · 0.8× [stem_boost]

required words: OR-group (systems | system)

risky rules only if WordNet verifies · 0.7×

WordNet synonyms + derivations, optional words only

stopwords and 1-2 letter words never looked up

an excluded word is never re-added

Morph +suffixes, kept if the form exists · 0.7 [morph_boost]

Fuzzy typed optional words only · 0.5^edits [fuzzy_decay]

max 10 per word · same first letter · edit budget from

length × (100 − confidence)

Typo swap einstien (2 docs) vs einstein (300+) → swap

[typo_swap_ratio 10×] unless other query words vouch

for the typed one [swap_context_check]

Typo evidence for auto: a swap fired, or a typed word

is in no document at all

Required, quoted and excluded words: stems only, never fuzzy

3 · Weigh — how rare is each term, which are noise

Term stats [SQLite] df + precomputed IDF per field

for every term, excluded words included

Corpus stopwords optional term in > 25% of docs → dropped

[highfreq_cutoff] ("united" is in 26% of bodies)

Fuzzy noise variant > max(1000, 3× origin df) → dropped

("start" is not a match for "smart")

Wildcards [SQLite] per field: commonest completions

under the cutoff, up to 100 or 200K rows

[max_wildcard_expansions] [wildcard_row_budget]

completions are exempt from the noise cut

(rarest-first, through 3.6: comp* never found computer)

-word* → doc-id set built in SQL, no rows loaded

4 · Retrieve — memory ∝ matched docs, not posting rows

Coverage bitmask one bit per original word

solar=1 · systems=2 · einstien=4 · prefix = one bit

variants set their origin's bit · one int (~40 B) per doc

Required words intersect, rarest first [SQLite]

stream the rarest (solar: 2,012 docs), then look each

next word up for the survivors only → 752

"the" is looked up for thousands of docs, never 270K

Is the rarest required word in ≤ 25% of docs?

yes → anchor on it; the set only shrinks [highfreq_cutoff]

no ("of the") → seed from the optional words, verify

every required word on the seed, top up with a capped

sample [broad_cap] → flagged truncated in diag

Optional words [SQLite] set bits; limited to the

survivors when required words exist

5 · Prune + fetch

Prune more than 5,000 candidates? [candidate_limit]

yes → keep the 5,000 with the most bits set;

ties keep stream order (title-field matches first)

no → keep all · exhaustive mode (limit 0) always keeps all

Two-phase [two_phase] collect candidates from the light

fields only, prune to [phase1_limit], then fetch all fields

Postings [SQLite] [field][doc][term] = tf, every field,

for the survivors only: required + optional + excluded

seek each (term, doc) pair by primary key, ids sorted,

≤ 900 per statement · or range-scan the terms and filter

in PHP when their rows < 6 × the pairs — cheaper wins

excluded words (moon) are read here for the first time:

exclusion happens after the prune, so earlier was waste

Positions [SQLite] phrase words only (solar, systems),

same docs · delta-coded blobs, decoded per doc

Doc lengths [SQLite] one batched read · BM25 family and

DFR use them; so do the title bonus and the tiebreaker

6 · Score — work ∝ survivors × terms

Filter every required group present · no excluded word

· phrase adjacent on the literal typed words → 27 docs

(no positions in the index → all phrase words in one field)

Score per field × field weight [title 3 · opening 2 · body 1]

bm25 · bm25+cov · bm25f · dfr · cover · idf · freq · rrf

term weight = IDF × trust boost: a variant adds recall

but never outranks the exact word

Coverage counts concepts: all forms of a word = one slot

Rarity credits a prefix with its rarest matched completion

(photo* → photobleaching, not photography)

Adjust proximity boost (BM25 family, DFR) · title bonus

full / half / partial by how much of the title the query covers

[title_bonus_*] · rrf: fuse bm25 + coverage ranks

7 · Present

Normalize best document = 100, the rest relative to it;

order untouched, scores comparable across algorithms

(raw bm25 5-70, coverage 0-100, rrf 0.01-0.1)

Sort score ↓ · then shorter title (token count): "Water"

before "Water pollution" · then doc id, so ties are stable

Total = docs with score > 0 · page = one slice of them

Titles + snippets [SQLite] for the page only, from the

optional documents table (absent → doc id as title)

snippet = opening cut at 300 chars [snippet_length],

escaped, then each word tokenized like the query and

<mark>ed when it is a matched term
